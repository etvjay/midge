02 · How it works

Group money, built at the level of the rules. Each part checks the one before it.

The room

Members seal their bids. Only the room can open them.

It weighs every bid or vote in secure hardware and proposes one payout. It holds no key to the money.

The rules

Set when the group is created and stored on NEAR: who may be paid, how much per round, until when. Anyone can read them, and the contract has no method to change them.

The payout

Paid only if it fits the rules. Anything else is refused and nothing moves.

The exit

If the room stops, each member takes their own share back.

07 · Under the hood

The parts, and what we call them in the code

The page uses plain words. The contract and the code keep older names, so here is the map, in case you read either.

The room

code: Roost

Opens the members’ sealed bids, works out the result, and signs one payout. It holds no key to the money. It runs on a host: an AI model on NEAR AI Cloud that the bids are sealed to, or our own program on Phala Cloud.

Model host live · Phala host attested on 4 and 8 Nov, not running now

The rules

code: Nest

The NEAR contract that holds the money: who can be paid, how much per window, until when. It refuses anything else, even with a valid signature.

c.fly-1793636729.testnet · live

Members

code: flyers

Anyone with a NEAR account. Each bid or ballot is sealed so only the room can open it, and signed so only its member could have sent it.

Signed bids · live on testnet

Opening a room

code: hatch

Creates a group with its rules. One-off rooms close after one task; ongoing rooms last across rounds.

One-off live · ongoing tested in the contract

The exit

code: escape hatch

After the exit timer, any member takes back what is left of their own money, alone. Nobody else’s share moves.

25 exits recorded

Settling

code: settle_batch

The contract pays what the room signed, if it fits the rules. A stuck payout can be finished by anyone after 100 blocks.

83 payouts · 36 refused

Two hosts

code: two-room agreement

One room run by two independent hosts that must both sign before any money moves: two cashiers stamping the same receipt.

Run with two local hosts; not on hardware yet

The advisor

code: advisor

An AI model in NEAR AI Cloud’s secure hardware that proposes how to split a total. It sees only the total, never a bid.

Proposed the split in a live round

      09 · What it cannot do

      The room cannot take the money. Only the rules can pay.

      It cannot take the money

      The room only proposes. Only the contract pays, and only within the rules every member agreed to.

      36 refused by the rules on testnet

      It cannot pay outside the rules

      An unlisted account or a payout over the cap is refused, and nothing moves.

      Recipient and cap checked in the contract

      It cannot lock anyone in

      If the room stops, every member takes their own share back after the exit timer.

      25 exits recorded

      One honest limit: on testnet our deploy key can still upgrade the contract, so the rules are only as fixed as that key. It is removed before mainnet (gap GAP-044).

      Questions, answered

      About Midge

      What is Midge?

      A network of private rooms with public rules, on NEAR. Any group (a fund, a DAO, a team, a set of AI agents) gets a private room to decide in, rules fixed in public that limit what the room can pay, and an exit each member can use alone. One contract on NEAR hosts many groups.

      Who is it for?

      Groups that decide together with money on the line: sealed-bid auctions and token sales, secret ballots that pay the winning option, payroll to one-time addresses, investing together, and AI agents that buy or pay together.

      What is live today, and what is not?

      Live on NEAR testnet: the contract with its rules, payouts and exit, bids sealed to a NEAR AI Cloud model, and limited agent keys. The SDK, API and MCP tools run on your machine. Attested but not running now: the room on Phala. Models only: lending quotes, block trades, shared AI. Next: paying out on Bitcoin, and moving the multichain payroll from our account to a group.

      Is this live? Can I lose real money?

      It is a working prototype on NEAR testnet, where coins have no value. There is no token, and no audit yet.

      Can I check any of this myself?

      Yes. Read the contract and its rules straight from NEAR, open any dot in the proof section on the public explorer, or run every test offline with one command.

      Money and safety

      Can the room run off with the money?

      No. The room holds no key to the money. It can only propose a payout, and the contract on NEAR pays it only if it follows the rules every member agreed to: who can be paid, how much per window, and until when.

      What if the room stops or disappears?

      Each member takes back what is left of their own money, with no one's permission, once the group's exit timer has run. Nobody else's share is touched.

      What stays private, and what is public?

      Private: what each member bids, votes or decides, and for payroll who owns each one-time address. Public: who deposited, how much, the rules, and every payout's amount and recipient.

      What stops a hijacked AI agent?

      Its key can do one thing: take its owner's money back out. In our recorded run, a tricked agent tried 9 ways to move money; all 9 were refused.

      Integrations

      What does Midge integrate with?

      NEAR testnet for the contract, NEAR AI Cloud for the model the room seals bids to, Phala Cloud for the room as its own program, NEAR Chain Signatures for addresses on other chains, and NEAR Intents' 1Click API for its asset registry. For agents: MCP tools, a JavaScript SDK and an HTTP API with live streams.

      How can an AI agent use it?

      Through the MCP tools, the JavaScript SDK or the HTTP API. Give the agent a limited key and the only thing that key can do on its own is take its owner's money back out.

      Does it work with other chains?

      Yes, on testnets. With NEAR Chain Signatures the Midge contract checked a group’s rules and asked the MPC network to sign a payment on Solana devnet and one on Ethereum Sepolia; both landed, and it refused three requests that broke the rules. Money held on other chains is outside the member exit, and nothing has been sent on Bitcoin.

      Does it use NEAR Intents?

      A recorded audit read the 1Click Swap API's asset registry: 210 assets across NEAR, Bitcoin, Ethereum and Solana. 1Click runs on mainnet only, so no swap has been made from testnet.

      Partners and tech

      Which partner technology does Midge use?

      NEAR Protocol (the contract, in Rust), NEAR AI Cloud (a model on Intel TDX whose report also carries NVIDIA GPU evidence), Phala Cloud (dstack confidential VMs on Intel TDX), NEAR Chain Signatures, NEAR Intents (1Click), public NEAR RPC (FastNEAR) and NearBlocks.

      How does NEAR AI Cloud fit in?

      Members seal their bids to a model running in NEAR AI Cloud's secure hardware, and the model proposes the split. Your browser can check that hardware on this page with a random number it picks.

      How does Phala fit in?

      The room can run as its own program in a confidential VM on Phala Cloud. It was run on real Intel TDX machines on 4 and 8 November; those machines were temporary and none is running now.

      Does Midge use OutLayer?

      Not yet. OutLayer runs one function per call on its own secure workers, each run with a fresh hardware report. Phala runs a whole machine we operate. Midge has a model of OutLayer-style spending limits for agents, but calls neither OutLayer nor a running Phala machine today.

      What is this site built with?

      Static HTML, CSS and JavaScript. The hero was rendered in Blender and is drawn live with three.js. Every figure comes from a recorded run or is read live from NEAR.
